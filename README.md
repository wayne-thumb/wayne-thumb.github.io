# 나동규 · 이엄지의 결혼 알림장

부부가 된 두 사람의 소식을 전하는 모바일 알림장입니다. 청첩장이 아니어서 별도의 결혼식은 진행하지 않으며 예식장, 오시는 길, 참석 안내, 달력, 디데이는 없고 날짜도 적지 않습니다.

색종이가 흩날리는 사진관 사진 위에 붓글씨 인사말이 써지고 같은 모양의 동그란 색종이가 터지며 시작해, 사진 37장을 보여 주고, 파란 하늘 아래 두 사람이 인사하는 사진으로 끝납니다. 색은 사진의 하늘·잔디·하트 풍선에서 가져왔고, 글꼴은 본문에 함렛(Hahmlet), 큰 인사말에 나눔손글씨 붓(Nanum Brush Script)을 씁니다. HTML·CSS·JavaScript로 작성했으며 백엔드가 없습니다.

배포 주소: https://wayne-thumb.github.io/

## 로컬 실행

Node.js 22 이상에서 실행한 뒤 http://127.0.0.1:4173 을 여세요.

```sh
npm run dev
```

```sh
npm run lint
npm run build
npm run preview
```

Windows PowerShell에서 `npm.ps1` 실행 정책 오류가 나면 `npm` 대신 `npm.cmd`를 사용하세요. 시스템 실행 정책을 변경할 필요는 없습니다.

`lint`는 JavaScript 구문을 검사합니다. `build`는 이름·배포 주소·사진 파일 같은 필수 값을 검증하고 배포할 파일만 `dist/`로 복사하며, 공유용 제목·설명을 설정에서 생성합니다. 모듈을 사용하므로 HTML 파일을 더블클릭하지 말고 로컬 서버로 확인하세요.

## 문구와 사진 수정

`invitation.js`에서 이름, 인사말, 사진 구성을 수정하세요.

- `headline`: 첫 화면 사진 위에 붓글씨로 한 줄씩 써지는 글입니다. 줄마다 따옴표로 나눠 적습니다.
- `message`: 소중한 분들께 전할 편지입니다. 빈 문자열은 문단 사이의 빈 줄입니다.
- `groom.family`, `bride.family`: 선택 사항입니다. 입력하면 소개란 이름 아래에 표시됩니다.
- `groom.portrait`, `bride.portrait`: 소개란의 아치 모양 인물 사진입니다. `shades`에 선글라스 사진을 적어 두면, 소개란이 처음 보일 때 두 사람이 함께 선글라스 사진으로 뒤집히고 어느 쪽을 눌러도 둘이 같이 바뀝니다.
- `intro.lead`: 소개 사진 아래에 크게 보이는 한 장입니다(지금은 선글라스 사진).
- `gallery`: 사진 묶음입니다. 묶음마다 큰 사진 한 장(`lead`)이 있고, `photos`의 처음 두 장은 비스듬히 놓인 인화 사진으로, 나머지는 옆으로 흘러가는 줄로 보입니다. `lead.effect`로 그 사진 위에서 움직이는 작은 효과를 고릅니다: `balloons`(하트 풍선), `bubbles`(비눗방울), `leaves`(은행잎), `sparks`(불꽃, `at`에 사진 안 불꽃 위치를 가로·세로 0~1로 적음). 빼면 효과가 없습니다. `title`은 묶음 위에 붓글씨로 써지는 제목이고(지금은 한낮 → 오후 → 해 질 녘 → 밤), `place`는 그 아래 작은 글입니다. 둘 다 빼면 보이지 않습니다. `tone`은 그 묶음 뒤 바탕색으로, 사진에서 가져온 색을 위에서 아래 순서로 적습니다(하나만 적어도 됩니다). 바탕은 그 색들을 지나 다음 묶음의 첫 색으로 이어지므로 묶음 전체가 한낮의 하늘색에서 풀빛, 노을빛, 밤까지 하나의 그라데이션이 됩니다. `night: true`인 묶음은 어두운 바탕에 맞게 글씨가 밝아지고, 그 묶음이 마지막이면 바탕이 마지막 인사 사진의 아침 하늘색으로 풀리며 이어집니다(계좌가 보이는 링크에서는 밤이 그대로 끝나고, 그 아래 계좌가 아침 하늘로 풀리는 바탕 위에 종이 한 장으로 놓입니다).
- `gift`: 마음 전하실 곳(계좌번호)입니다. 아래 "링크 두 가지"를 보세요.
- `welcomeConfetti`: 첫 화면이 열리자마자 양옆에서 터지는 동그란 색종이입니다. `false`로 끌 수 있습니다. 색은 `confetti.js`의 `studioConfetti`에 있습니다.
- `siteUrl`: 배포 주소입니다. 도메인을 바꾸면 함께 바꾸세요. 메신저 공유 미리보기 사진 주소에 쓰입니다.

### 움직임

움직임은 모두 `motion.js`에 있습니다. 첫 화면 사진은 고정된 채 편지가 종이처럼 그 위로 올라오고, 글과 사진은 스크롤에 맞춰 자리를 잡습니다. 사진 줄은 스스로 천천히 흘러가며, 화면을 위아래로 넘기는 동안에도 계속 흐릅니다. 줄을 직접 옆으로 밀면 잠시 멈췄다가 놓은 자리에서 다시 흐릅니다. 마지막 인사 사진에 닿으면 두 사람의 손글씨가 획 하나씩, 쓰는 순서대로 써집니다. 기기의 "동작 줄이기" 설정이 켜져 있으면 이 모든 움직임과 꽃가루 없이 정지된 화면으로 보입니다.

페이지는 새로고침하거나 다시 돌아와도 항상 맨 위에서 열립니다. 등장 효과는 아래로 내려갈 때만 재생되고, 위로 올라가며 처음 만나는 부분은 효과 없이 제자리에 놓여 있습니다.

### 링크 두 가지

같은 페이지를 두 가지 주소로 보낼 수 있습니다.

| 보낼 링크 | 보이는 내용 |
| --- | --- |
| `https://wayne-thumb.github.io/` | 소식만 전합니다. 계좌번호는 보이지 않습니다. |
| `https://wayne-thumb.github.io/p` | 사진 아래에 "마음 전하실 곳"이 보입니다. 신랑·신부 이름이 한 줄씩 있고, 이름 옆 "계좌 보기"를 누르면 그 사람의 은행·계좌번호·예금주와 복사 버튼만 펼쳐집니다(다시 누르면 접힙니다). |

계좌는 `invitation.js`의 `gift.accounts`에 `{ label: '신랑 나동규', bank: '○○은행', number: '000-00-0000000', holder: '나동규' }` 형태로 적습니다. 목록을 비우면 두 링크 모두 계좌를 표시하지 않습니다. 페이지 안의 공유·링크 복사 버튼은 지금 열려 있는 주소를 그대로 보냅니다.

`/p` 링크는 메신저 미리보기와 브라우저 탭 제목 맨 앞에 ❤️가 붙어 두 링크를 구분할 수 있습니다. `/p`는 `invitation.js`의 `gift.path` 값이며, 빌드할 때 같은 페이지가 `p/` 폴더에도 만들어집니다. 그래서 `npm run dev`(빌드 없이 원본을 그대로 보여 줌)에서는 `/p` 대신 `/?mode=p`로 확인하고, 실제와 똑같이 보려면 `npm run build` 후 `npm run preview`로 `/p`를 여세요.

**링크를 나눈 것일 뿐 잠금 장치가 아닙니다.** 주소 뒤에 `/p`를 붙이면 누구나 볼 수 있고, 이 저장소는 공개 저장소라 적어 둔 계좌번호는 코드와 git 기록에도 남습니다.

### 사진 바꾸기

사진은 `id`로 가리키며 `assets/photos/<id>-640.webp`, `<id>-1280.webp` 두 크기가 있어야 합니다(첫 화면과 마지막 사진은 `-1920`도 사용). 원본(`웨딩/` 폴더, 4GB가 넘어 `.gitignore`로 제외)에서 다시 만들려면 `scripts/photos.mjs`의 목록을 고친 뒤 실행하세요. 공유 미리보기용 `assets/og.jpg`도 함께 만들어집니다.

첫 화면 사진(`cover`)은 배경이 한 가지 밝은 색인 사진관 컷이어야 합니다. 사진 가장자리를 같은 색 바탕에 녹여 넣고 그 위 빈 곳에 인사말을 놓기 때문입니다. 다른 사진관 컷으로 바꾸면 `styles.css`의 `.cover` 배경색도 그 사진의 배경색에 맞춰 주세요.

```sh
npm install
npm run photos
npm run photos -- portrait-bride cover   # 적은 id 만 다시 만들기
```

`npm run build`는 `invitation.js`가 가리키는 사진 파일이 모두 있는지 확인하고, 없으면 파일 이름과 함께 실패합니다.

마지막 인사 사진의 두 사람 머리 위에는 손글씨가 하나씩 있습니다. `assets/thanks_thumb.svg`는 신부가 직접 쓴 글씨이고, `assets/thanks_wayne.svg`는 신랑 것으로 클로바 나눔손글씨 "손편지체"로 쓴 글자를 한 자씩 흐트러뜨리고 신부의 펜 굵기에 맞춰 그림으로 만든 것입니다. 같은 이름의 흰색 SVG로 바꿔 넣으면 그대로 교체됩니다(크기가 달라지면 `index.html`의 `width`·`height`도 맞춰 주세요). 써지는 연출은 SVG 안의 `<path>` 하나를 펜이 한 번 닿은 획으로 보고 왼쪽 위부터 차례로 드러내는 방식이라, 획마다 `<path>`가 나뉘어 있어야 자연스럽습니다. 글씨가 기운 각도와 시작 시각·걸리는 시간은 `app.js`의 `handwrite(...)` 두 줄에 있습니다. 위치와 크기는 `styles.css`의 `.thanks-bride`, `.thanks-groom`에 사진에 대한 비율로 적혀 있습니다.

사진은 눌러도 크게 열리지 않고, 길게 누르거나 우클릭해도 저장·복사 메뉴가 뜨지 않으며 끌어다 놓을 수도 없습니다(`styles.css`의 `img` 규칙과 `app.js`의 `contextmenu` 처리). **무심코 저장하는 것을 막을 뿐 잠금 장치가 아닙니다.** 화면 캡처는 웹페이지로 막을 수 없고, 이 저장소는 공개 저장소라 사진 파일도 그대로 받을 수 있습니다.

공유는 휴대폰의 기본 공유창을 사용하고, 지원하지 않으면 링크를 복사합니다. 검색 엔진에는 노출되지 않도록 `noindex`를 넣어 두었습니다. 축하 메시지 수집(방명록)처럼 서버가 필요한 기능은 포함하지 않습니다.

## QR 코드

`npm run qr`은 소식만 전하는 주소(`https://wayne-thumb.github.io/`)의 QR 코드를 `qr/` 폴더에 PNG(1400×1400)로 만듭니다. 계좌가 보이는 주소(`/p`)용은 어른들께 드릴 `qr-heart-p` 한 장만 만듭니다. 모서리가 진한 빨강이고 가운데에 빨간 하트가 있어서(그 링크 제목 앞의 ❤️와 같은 하트) 기본 주소용과 한눈에 구분됩니다.

| 파일 | 모양 |
| --- | --- |
| `qr-plain` | 사진 없이 검은 점만 있는 QR |
| `qr-heart-p` | `/p`용. 빨간 모서리, 가운데 빨간 하트 |
| `qr-sunglasses` | 검은 점 QR 가운데 동그란 창에 선글라스 사진 |
| `qr-night` | 가운데 창에 불꽃을 든 두 사람, 점마다 같은 밤 사진이 비침 |
| `qr-dots-skyline`, `qr-dots-sparkler`, `qr-dots-sunglasses`, `qr-dots-shades-close` | 사진 전체 위에 흰 점·검은 점을 찍은 모양 |

만든 그림을 여러 크기로 줄이고 흐리게 해서 다시 읽어 보고, 주소가 그대로 나오지 않으면 실패합니다. 그래도 인쇄하거나 돌리기 전에 실제 휴대폰 카메라로 꼭 찍어 보세요. 사진 위에 점을 찍은 모양은 가운데 사진 모양보다 덜 안정적입니다. 인쇄할 때는 가로 2.5cm 이상으로, 바깥 흰 여백을 자르지 마세요.

QR에는 주소가 그대로 들어 있어서, 주소가 바뀌면(`siteUrl`, `gift.path`, 조직 이름) 다시 만들어야 하고 이미 인쇄한 것은 쓸 수 없습니다.

```sh
npm install
npm run qr
```

## GitHub Pages

`main`에 push하면 `.github/workflows/pages.yml`이 구문 검사 → 빌드 → Pages 배포를 실행합니다. GitHub **Settings → Pages → Build and deployment → Source**는 **GitHub Actions**로 설정합니다. 진행 상황은 저장소의 **Actions**에서 확인합니다.

```sh
git add -A
git commit -m "feat: update wedding announcement"
git push origin main
```

저장소는 `wayne-thumb` 조직의 `wayne-thumb.github.io`입니다. 이름이 `<조직 이름>.github.io`인 저장소라서 주소 뒤에 저장소 이름이 붙지 않고 `https://wayne-thumb.github.io/`로 바로 열립니다. 조직 이름을 바꾸면 저장소 이름도 `<새 이름>.github.io`로 바꾸고 `invitation.js`의 `siteUrl`을 고쳐 다시 배포해야 하며, 예전 주소는 새 주소로 넘어가지 않고 끊깁니다.

## 나중에 도메인 연결하기

현재 `wayne-thumb.github.io` 주소는 무료로 사용할 수 있습니다. 별도 도메인이 없어도 배포할 수 있습니다. 무료 도메인/서브도메인 제공 업체는 DNS 레코드 수정 권한과 제공 기간·갱신 조건을 확인한 뒤 선택하세요. 별도 도메인은 아직 등록하거나 연결하지 않았습니다.

1. 사용할 도메인을 확보하고 GitHub에서 도메인 소유권을 검증합니다.
2. 저장소 **Settings → Pages → Custom domain**에 주소를 입력합니다.
3. 서브도메인은 DNS `CNAME`을 `wayne-thumb.github.io`로 설정합니다.
4. 루트 도메인은 GitHub 문서의 최신 `A` 또는 `ALIAS`/`ANAME` 레코드를 사용합니다.
5. DNS 반영과 인증서 발급 후 **Enforce HTTPS**를 켭니다.

모든 리소스가 상대 경로여서 도메인이 바뀌어도 동작합니다. GitHub Actions 배포 방식에서는 `CNAME` 파일 대신 저장소 Pages 설정에서 도메인을 관리합니다.

- [GitHub Pages 배포 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
- [사용자 지정 도메인 연결](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)
